Why this design

1 · The problem with the current dashboard

Seven KPI cards rendered at identical weight — New, Pending, Assigned, Service Done, Completed, Cancelled, All. Everything is equally loud, so nothing is. Completed (41) and Cancelled are archives that need no decision, yet they occupy the same real estate as New, which is the only tile that represents money at risk.

The counts are also filters, not insight. They answer "how many are in state X", never "what is going wrong and what does it cost me".

2 · Goal → Signal → Metric

Google's GSM framework: never put a number on screen until you can name the goal it serves and the decision it drives.

GoalSignalMetric on screen
No lead is left waitingUnassigned age climbingUnassigned > 2h + oldest wait
Promises are keptScheduled slot approachingSLA at risk today + countdown
Customer feels heardInbound WhatsApp unansweredUnread replies + age
Cash isn't leakingIssued parts never reconciled₹ unreconciled + technician count
Field capacity is used wellLoad skew across techniciansPer-tech load bar + live state

3 · HEART, mapped to this business

  • Happiness → CSAT 4.6 from 9 rated jobs, surfaced on the hero card instead of buried in a table column.
  • Engagement → activity feed; the desk should feel alive without the operator refreshing.
  • Adoption → % of tickets that complete WhatsApp intake without a human touch (next iteration).
  • Retention → reopened-this-week counter in the pipeline footer — a reopen is a failed job.
  • Task success → first-visit fix rate 86%, plus the two median cycle times under the pipeline.

4 · Information hierarchy

Three altitudes, read top to bottom in about eight seconds:

  • Act — "Needs action": four decisions ordered by cost of delay. Each is a verb, not a noun.
  • Assess — Booked today (with 14-day trend) and the pipeline as a proportional flow, so a bulge is visible as shape rather than read as digits.
  • Investigate — the queue, sorted by urgency by default, with waiting-time encoded as colour so triage is pre-attentive.

Stage counts remain clickable filters, so nothing you can do today is taken away — it is re-ranked.

7 · Accessibility floor

  • Body text ≥ 4.5:1 in both themes; urgency is never colour-alone (bar + text + label).
  • Every interactive element is a real <button> or <a> with a visible focus ring.
  • Filters expose aria-pressed; sort exposes role="tablist"; the feed is an aria-live region.
  • Ctrl/⌘K palette, Esc to dismiss, arrow keys to navigate — a keyboard operator never has to reach for the mouse.

8 · What this costs to build

  • Reuses the existing token seed (brand #0f766e), Tailwind config and card/badge primitives.
  • Needs four new backend aggregates: unassigned-age, SLA risk, unreconciled ₹, and daily booked/CSAT rollups.
  • Technician load and live state come from data you already collect (assignments + location).
  • No animation library. All motion above is CSS + the Web Animations API — same constraint the technician app runs under.
